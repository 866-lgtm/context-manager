- A strategy's `onNewMessage` that throws before returning, or returns no promise, no longer escapes `addMessage` after the message is stored. A throw is logged as a rejection is, and a hook that returns no promise is no failure. Either way the message stays stored: `addMessage` returns its id, a sharded body keeps all its shards, where before the whole body was removed and the add refused, and an `onMessage` listener registered after the manager still hears the add. Before, a throw escaped `addMessage` with the message stored, and a hook returning no promise threw a `TypeError` the same way. The bundled strategies' hooks are `async` and never did either. The hook still runs inside the write, so its synchronous part comes before `addMessage` returns. The failure's log line, a rejection's included, now names the message: `Strategy onNewMessage failed for message <id>:` (#288).
