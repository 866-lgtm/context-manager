- The live window's image limits count every `image` block, whatever its source (base64, a `data:` URL or a remote URL), and every `generated_image`, top-level or nested in a tool result: the images the compression image cap sees. `maxLiveImages` counted only top-level `image` blocks, and `maxLiveImageBytes` only a base64 source's bytes, so images nested in tool results and generated images weren't limited at all, and a `data:` URL image counted toward the number but not the bytes. Both strategies' strip, the autobiographical strategy's image watermark and its post-strip estimates now count them all, so a window holding such images keeps fewer of them live than before, and the rest become the window's placeholder. A stored window where these counts now bind renders differently after the upgrade, so its first request misses the prompt cache. A tool result whose nested image is replaced gives up its replay form (`rawItem`, `rawXml`), and so does every block of its message that shares that form, so the formatter can't send the image from it. An image inside an opaque provider item, such as a Responses `image_generation_call`, which membrane keeps only as its raw form, still isn't counted. `AutobiographicalStrategy.imageBlockBytes`, which subclasses can call, gives the same inline sizes, where it counted base64 sources only.
- A `generated_image` block is priced like an `image` without a `tokenEstimate`: 1,600 tokens, where the store priced it at 0. Membrane sends a generated image to the provider as an image, so a layout holding one ran larger than its estimate. Stores holding generated images now estimate larger and may fold or strip more, and the fold planner weighs a top-level generated image as an image: the estimate now counts what is sent, at the store's flat image price. Since the price changed, a calibration multiplier learned under any earlier pricing epoch, or with no stamp (0.13.0 or earlier), is discarded in a store holding a generated image, top-level or nested: it restarts from 1, which the first provider sample within the calibration's sanity band sets. A provisional 1, the restart of an earlier discard that no sample has confirmed yet, is kept there instead, re-stamped and still provisional, with the reset that records what it replaced. In a store without a generated image, a multiplier is kept or discarded as before, so one stamped with the previous epoch is kept and re-stamped. The protected `formatChunkForCompression`, which no built-in path calls, marks a top-level generated image `[Image]` where it wrote nothing for one, so a subclass that sends its transcript sends new bytes for a chunk holding one. A stored window that any of this re-renders, by a generated image's new price or a discarded multiplier, misses the prompt cache on its first request after the upgrade, as one whose image counts now bind does.
- Where `adaptiveResolution` is on, the autobiographical strategy's strip counts the images of a message no entry sends, such as one a fold left out, as its post-strip estimates, which that selection budgets by, always have, so the two keep and strip the same images. Such a message's images took live slots in the estimate and none in the strip, so a window kept images that its estimate had priced as the placeholder, and sent more than it planned for. Count and bytes go newest-first, and a folded chunk is older than the recent window, so the images this newly strips sit in raw messages older than a folded one, such as the head window's, whose slot a folded message's image takes. A window with folds can then keep fewer live images than its limits allow, and it no longer sends more image than it planned for. A stored window this re-renders misses the prompt cache on its first request after the upgrade. The hierarchical selection, the default, prices the messages it emits at the store's full estimate, apart from a message `maxMessageTokens` caps, priced at most at the cap plus 50, where the price leaves out its images. It prices no image it emits as the placeholder, so its strip still counts only the images it sends.
