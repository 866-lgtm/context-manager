- A store holding a summary whose `sourceIds` is null no longer throws on every compile under adaptive resolution. Opening a store now repairs every summary that readers can't use: empty text, sources that aren't a list of ids (null, a string, an empty list, or a list holding something other than ids), or a range that isn't two ids. An L1 with unreadable sources takes them from the compressed chunk record that names it, or else from another copy of itself, and its range is always its sources' ends; a summary above L1 takes sources and range together from another copy. Copies of one id keep the text of a non-empty copy, and each parent pointer (`parentId`, `mergedInto`) keeps a value that names a kept summary, from any copy. A summary that can't be recovered is dropped, and so is every summary above it that names a summary no longer in the store, including one an earlier version dropped: on upgrade, a store where an earlier version dropped an empty summary loses the summaries above it once, and their surviving sources merge again. A parent pointer that names no kept summary is cleared, chunk records whose L1 is gone are reopened, and queued merges naming a missing summary are removed. The repair is persisted, so a second open changes nothing, also when the store is opened with `auditOnly`; its log line names the summaries dropped, for each reason, and those rebuilt. A live lookup of an L1 another instance appended adopts it as the loader would keep it.
