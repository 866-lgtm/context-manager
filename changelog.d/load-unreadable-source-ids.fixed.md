- A store holding a summary whose `sourceIds` is null no longer throws on every compile under adaptive resolution. Opening a store now repairs every summary that readers can't use: empty text, sources that aren't a list of ids (null, a string, an empty list, or a list holding something other than ids), or a range that isn't two ids. An L1 with unreadable sources takes them from the compressed chunk record that names it, or else from another copy of itself, and its range is always its sources' ends; a summary above L1 takes sources and range together from another copy. Copies of one id keep the text of a non-empty copy. A summary's parent is the first pointer on any of its copies, `parentId` before `mergedInto`, that names a kept summary at a higher level listing it among its sources; `mergedInto` is set to that parent, and so is a `parentId` naming anything else. A summary that can't be recovered is dropped, and so is every summary above it that names a summary no longer in the store, including one an earlier version dropped: on upgrade, a store where an earlier version dropped an empty summary loses the summaries above it from its active summaries once, and their surviving sources merge again. A parent pointer that names no such parent is cleared, and a null one counts as none. Chunk records whose L1 is gone are reopened, and queued merges naming a missing summary are removed. The repair is persisted, so a second open changes nothing, also when the store is opened with `auditOnly`; its log line names the summaries dropped, for each reason, those rebuilt, those given a parent and those whose parent pointers it cleared. A live lookup of an L1 another instance appended adopts it with its range derived from its sources and its parent pointers as the store has them. A message whose saved fold level names a summary that is gone is planned from the deepest summary still over it at or below that level, so the solvers fold it to its surviving L1 instead of rendering it raw. The next compile that commits saves the level it presented, except for a locked message, which keeps its saved level. Where the budget can't hold the summaries still over such messages, a compile is refused as over budget, as for any store whose summaries outgrow its budget.
