- A store holding a summary whose `sourceIds` is null no longer throws on every compile under adaptive resolution. Opening a store now repairs every summary that readers can't use: empty text, sources that aren't a list of ids (null, a string, an empty list, or a list holding something other than ids), or a range that isn't two ids. An L1 with unreadable sources takes them from the compressed chunk record that names it, or else from another copy of itself, and its range from their ends; a summary above L1 takes both from another copy. Copies of one id keep the text of a non-empty copy and the parent of any copy that has one. A summary that can't be recovered is dropped, and so is every summary above it that names a summary no longer in the store, including one an earlier version dropped: on upgrade, a store where an earlier version dropped an empty summary loses the summaries above it once, and their surviving sources merge again. Their children are unmerged, chunk records whose L1 is gone are reopened, queued merges naming a missing summary are removed, and the repair is persisted and logged with the ids involved, also when the store is opened with `auditOnly`. A live lookup adopts an L1 another instance appended only if it passes the same checks.
