- A compression attempt's provider input count adds cache writes and cache reads to `inputTokens` for every provider, as membrane 0.5.81 and later report them, not only for Anthropic and Bedrock (#182). On OpenAI, and on Gemini once membrane counts its cache the same way (antra-tess/membrane#109), the count left out the cached span. A refused compression's fallback plan then took a baseline too small, and could send an expanded fallback that doesn't fit the compression budget instead of recording it as `admission_rejected`. A successful attempt's `renderedTokens` under-reported its prompt by the same span.
  - **Host operators:** on those providers, a fallback that doesn't fit is now `admission_rejected`, as it is on Anthropic, where it was sent before. With a membrane before 0.5.81, or an adapter whose cache convention membrane declares `unknown` (Gemini until that membrane change, and the OpenAI-compatible and OpenAI completions adapters), a cached response's input can be counted twice over its cached span, which only makes admission stricter.
  - A response that reports no fresh input but a positive cache read now counts as the provider's observation of the prompt on every provider, as it already did on Anthropic. A response with no input count, or a zero total, still falls back to the complete request bound.
