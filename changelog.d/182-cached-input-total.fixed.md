- A compression attempt's provider input count adds cache writes and cache reads to `inputTokens` for every provider, not only for Anthropic and Bedrock (#182). membrane states those three counts as disjoint wherever it knows the convention, so on the other providers that report cache reads, OpenAI's adapters, OpenRouter and, from membrane 0.6.0, Gemini, the count left out the cached span. A refused or incomplete compression's fallback plan then took a baseline too small, and could send an expanded fallback that doesn't fit the compression budget instead of recording it as `admission_rejected`. A successful attempt's `renderedTokens` under-reported its prompt by the same span.
  - **Host operators:** on those providers, a fallback that doesn't fit is now `admission_rejected` and not sent, as on Anthropic and Bedrock, and `renderedTokens` includes the cached span. A full cache hit, no fresh input beside a positive cache read, now counts as the provider's count of the prompt there too, where before the complete request bound stood in for it.
  - The compression budget's accounting version is 3. A version-2 quarantine record still holds its chunk where the corrected count would plan the same fallbacks: its plan rejected every expansion on the provider's count, or had none, and it ran no tool-prose hoist, so the larger count alone rejects those expansions again. Any other version-2 record no longer counts toward the per-chunk shape cap, so its chunk gets a fresh attempt: a plan that sent an expansion on the provider's count, which may now be over the budget and leave that attempt to one that fits; a plan priced on the complete request bound because version 2 read no count, as it read a full cache hit outside Anthropic and Bedrock, which version 3 counts; and a record that ran a hoist, which earlier releases sent without pricing it against the budget. After upgrading, such a chunk gets a fresh cap of three shapes: one attempt at its current shape, and more only if its shape changes. A re-quarantine raises a fresh `compression:quarantine-alert`, since the alert is keyed by the record. A record names its model but not its provider, and doesn't say why version 2 read no count, so the retry also reaches chunks the corrected count can't change: an Anthropic or Bedrock plan that sent an expansion, whose count was already right, and a plan priced on the bound because the provider reported no usage. Those retries usually end as before, at the cost of the canonical call and any fallbacks that fit. Version-2 records stay until the chunk compresses, the paid-off sweep or an operator's clear removes them, or the ledger's checkpoint keeps only its newest 1,024. Going back to a release before this one gives a chunk whose records are all version 3 one fresh attempt the same way, since an earlier release counts only version-2 records. A chunk that still has version-2 records, such as one this upgrade retried and quarantined again, is counted by them as before the upgrade.
  - The `@animalabs/membrane` range is `^0.6.0`, the first release that states Gemini's cached input apart from its fresh input (antra-tess/membrane#109). It also adds Gemini's tool-use prompt tokens, which Google's own tools such as code execution add to a prompt, to the input count (antra-tess/membrane#125). The strategy counts through `ctx.membrane`, the host's instance, so a host must take 0.6.0 or later in its own `@animalabs/membrane` range too. A host whose membrane is older passes Gemini's counts raw, and before 0.5.81 OpenAI's too, with the cached span inside the input count, so the sum counts that span twice, and a fallback that fits can be `admission_rejected`.
