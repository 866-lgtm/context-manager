- `OverBudgetError.clearedBy` names what clears an over-budget refusal at run time besides a larger budget, which clears any of them: `'compression'` while compression work that would shrink the context is running or queued for the drain to take, which a compression hold or the speculative cap can stop (for the adaptive picker, only while its plan still has summaries to produce), `'newer-message'` when the newest message alone is over (windowed passthrough) and a newer one that fits would move past it, and `'smaller-recent-window'` when the raw recent window is what's over and the head fits beside the newest turn as the compile must keep it raw: the newest message (for one split into shards, its newest shard), or, when the newest message's body holds a `tool_result`, that whole body and the call before it, or everything from a compression hold that starts earlier. It doesn't name compression for a chunk that needs a model call while the compression quarantine holds it (tick skips it, though a request of a new shape gets a fresh attempt), for a chunk tick defers until the host declares its tools, or, without a compression model, for a merge or a chunk only a model call settles. When there's no compression model or the quarantine can't be read, it doesn't name compression for anything queued behind a chunk only a model call settles: tick throws at such a chunk, and a host's tick loop ends there. Where tick would instead defer that chunk until the host declares its tools and go on, the count stops there too, since it reads tool blocks as stored. It's empty when nothing else is known to clear the refusal. A dry run's `PreviewResult.clearedBy` carries the list for a layout that doesn't fit, the plan's own when the plan is over the budget; it names compression only for work queued when the dry run takes the list, not for what its plan's own ops would queue. A host can now tell whether compression work that can make room is under way without reading the message, though whether that work is enough to fit isn't checked. The list's type is exported as `OverBudgetClearedBy`; the messages are unchanged.
