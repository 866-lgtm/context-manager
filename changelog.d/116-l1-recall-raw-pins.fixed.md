- The canonical L1 compression prompt honors raw (level-0) pins. The live selector already did, but the prompt still recalled the summary covering a pinned span. A frontier summary that covers a force-raw message is now descended rather than recalled: its children take its place, so only the branch containing the pin opens and the raw added is just the pinned L1 chunks (sibling branches stay summarized). Empty-content frontier summaries are descended the same way instead of exposing their whole span raw. Merge recall, L3+ merge inputs, transition summaries and the source-only L1 do not consult pins.
- A pin resolves once, for compression, chunking and every selector (`AutobiographicalStrategy.resolvedPinBounds`). Level bounds are read only under `foldingStrategy: 'kv-stable'` and `'kv-unified'` with `adaptiveResolution`, with kv-stable's precedence: where pins overlap at a message, a bound takes a classic pin's place, `level` takes `maxLevel`'s, and the lowest of each kind wins; a level or cap of 0 is raw. Under every other selector a pinned message is raw, as `pinAtLevel` documents, so the flat-profile and oldest-first folders no longer fold a message pinned with a level. Picker chunks carry one reading: a raw pin, a level or cap of 0 included, is `pinned`, so kv-unified no longer asks for an L1 of a chunk pinned at level 0, and `pinLevel` and `pinMaxLevel` are set only above 0. Under kv-unified, a `level` and a `maxLevel` that overlap no longer conflict: the `level` applies, as under kv-stable. Under kv-stable and kv-unified, a message pinned at a level or cap above 0 before it was compressed is now compressed, since only a summary can supply its level; before, the chunker skipped every pinned message, so it stayed raw.
