- Compression requests prepare an independent copy of their messages before admission, hashing and dispatch. Canonical and recall-curve candidates are built from authored answers, then prepared separately; projecting a parent no longer suppresses its child expansion, and expanded children receive the same projection. Source-only, split, merge, mode-rewrite and transition requests use the same preparation.
- Preparation replaces serialized `data:<mime>;base64,…` URLs with markers when their matched payload contains at least 4096 characters, including JSON slash escapes. Markers count serialized payload characters. Text and string or block-array tool results are covered; existing unquoted MIME parameters and escaped slashes remain supported. Line-wrapped and bare base64 remain outside this projection. Chronicle content stays unchanged.
- Edited blocks and siblings sharing their replay forms release those forms, so old serialized data cannot be replayed instead of the marker. Unchanged blocks and nested arrays retain their identities and replay forms. Nonzero replacement counts describe preparation of a candidate, separately from its dispatch.
- Both image-byte caps count inline `data:` URL image sources and MCP-shaped `{ type: 'image', data, mimeType }` blocks. Compression caps also cover images inside tool results. The live policy continues to cover top-level image blocks.
