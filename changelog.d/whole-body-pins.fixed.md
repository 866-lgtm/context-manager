- **Pins and document marks render whole messages.** A pin whose first or last id names one part of a message stored in parts (a long message that ingress splits under `adaptiveResolution`) now covers that message from its first part to its last in the adaptive-resolution selects, what the agent is sent. The summarizer's prompt still reads a pin by its ids: it has the message's other parts as summaries, and carrying them raw multiplied later compression requests' input. Before, it covered only the parts its ids named, so a document mark on a long message, made with the id of its first part as connectome-host's web panel makes it, kept that part raw and let the rest fold. Compression still reads a pin by its ids, so the message's other parts are chunked and summarized as before.
  - **When the whole messages don't fit.** A compile refused over budget narrows pins back to their own ids, one at a time, the one whose whole messages add the most that compression has summarized first, until a select goes ahead. Where compression has kept up, those parts are summarized already, so that select can send their summaries, as compiles did before this change. A narrowed pin stays narrowed until the store is loaded again (an open, a branch switch or a fork), and a warning names it and says how to have it whole again. Nothing is stored: a store loaded again, as at a restart, reads every pin whole, so after the budget is raised the whole message comes back, and one that still doesn't fit is narrowed again at its first refused compile. When no narrowing lets the compile through, the pins go back and the refusal stands. A refusal whose middle holds nothing, as when the head and recent windows alone are over the budget, narrows nothing. A dry compile narrows for itself only.
  - **Upgrade.** A stored mark on part of a long message reads whole. Where the whole message fits, the first compile after the upgrade rewrites the request once, from that message on; under kv-unified, whose solver weighs the whole request, the rewrite can start earlier. Where it doesn't, the first compile narrows the mark and warns, and in a store with that one mark it sends the request the earlier version would have sent.
